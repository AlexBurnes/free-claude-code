# Переключение версий FCC

На компьютере доступны два отдельных окружения FCC:

- `upstream` — оригинальный FCC **v6.16.0** без наших изменений.
- `fork` — наша версия с именованными профилями и исправлениями.

Ими управляет одна пользовательская служба `fcc-server.service`. Переключатель сначала останавливает текущий сервер, затем запускает выбранный и проверяет его готовность. Две управляемые версии одновременно не запускаются. Перед переключением завершите или приостановите агентские задачи: текущие запросы будут прерваны.

После слияния v6.16.0 13 октября 2026 года оставлена запущенной **наша версия (`fork`)**. Автозапуск включён и использует сохранённый выбор. Адрес Web UI: **http://127.0.0.1:8082/admin**.

## Посмотреть работающую версию

```bash
fcc-version status
```

В выводе `selected` — сохранённый выбор, `active_runtime` — версия фактически работающего процесса. При нормальной работе значения совпадают, `ActiveState` равно `active`. Пути окружений и поле `version` помогают различить сборки.

## Запустить оригинал

```bash
fcc-version use upstream
fcc-version run claude
```

Чтобы открыть существующую беседу Claude Code:

```bash
fcc-version run claude --resume
```

Оригинал использует модели из общей страницы **Model Config**. Параметр `--fcc-profile` в нём не поддерживается.

## Переключиться на нашу версию

```bash
fcc-version use fork
fcc-version run claude --fcc-profile openai
```

Вместо `openai` укажите имя своего сохранённого профиля. Запуск без профиля использует общий Model Config:

```bash
fcc-version run claude
```

После перезапуска сервера заново запустите агента с именованным профилем: привязки активных сессий не сохраняются при остановке сервера. Для продолжения беседы можно добавить нативный параметр `--resume`.

## Другие агенты

Если соответствующий CLI установлен:

```bash
fcc-version run codex
fcc-version run pi
fcc-version run opencode
```

Аргументы после имени агента передаются его launcher. На этом компьютере обычный `fcc-claude` также запускает launcher выбранной версии через переключатель. Без `--fcc-profile` он использует Model Config. Другие ранее установленные команды и команды профилей могут оставаться привязанными к старому пакету; для сравнения используйте `fcc-version run …`.

## Перезапуск и автозапуск

```bash
systemctl --user restart fcc-server.service
systemctl --user status fcc-server.service
journalctl --user -u fcc-server.service -f
```

Перезапуск и следующий вход в систему используют сохранённый выбор версии. Состояние автозапуска службы сохраняется при установке переключателя. Не запускайте вручную второй `fcc-server` и не переустанавливайте службу старым `fcc-systemd-user.sh`: он заменит команду переключателя.

Web UI на текущей установке: **http://127.0.0.1:8082/admin**.

## Настройки и сравнение API-ошибок

Обе версии используют общие OAuth-аккаунты, базы и историю в `~/.fcc`. Настройки `.env`, включая API-ключи и Model Config, сохраняются отдельно для каждой сборки. Переключатель восстанавливает нужный файл только после остановки сервера. Это необходимо: После merge v6.16.0 наша версия и текущий оригинал используют схему2; сохранённый старый оригинал v6.10.5 требует схему1. Слот нашей версии мигрирует при первом запуске, старый слот оригинала сохраняется отдельно. Первоначальные настройки скопированы; последующие изменения в Web UI независимы. Перед переключением создаётся закрытая резервная копия в `~/.local/share/fcc-versions/backups/`; она содержит учётные данные и не предназначена для публикации.

Сравнивайте одну модель, один аккаунт и одинаковые параметры reasoning/fallback. Начните с новой короткой беседы в каждой версии, затем отдельно проверьте проблемную историю через `--resume`. Запишите время, модель и request ID ошибки. Оригинальный launcher задаёт окно auto-compact 190000 токенов; наша версия позволяет его настроить, поэтому длинная беседа может вести себя по-разному.

При неудачном запуске переключатель пытается вернуть прежнюю версию. Он возвращает точную предыдущую `.env`, но не перезаписывает OAuth-аккаунты и базы и не завершает посторонний процесс, занявший порт. Подробности установки и проверок: [сравнение с оригиналом](version-comparison.md).

## Откат оригинала

Старый оригинал v6.10.5 сохранён в `../free-claude-code-upstream`. Из каталога нашей версии:

```bash
bash scripts/fcc-versions-install.sh \
  --fork-bin "$PWD/.venv/bin" \
  --upstream-bin "$(realpath ../free-claude-code-upstream/.venv/bin)"
fcc-version use upstream
```

Для возврата на v6.16.0 замените последний путь на `../free-claude-code-upstream-6.16.0/.venv/bin`. Перерегистрация перезапускает сервер. На GitHub точный баг с bare `rs_…` не подтверждён как исправленный: [результаты проверки upstream](upstream-update-2026-10-13.md).
